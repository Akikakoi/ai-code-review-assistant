# 0004 · 上下文默认层级：默认 L1 + L2，L3 按条件触发

- 状态：已采纳
- 日期：2026-09-13
- 相关：`src/acra/context/builder.py`、`src/acra/analysis/risk_rules.py::l3_triggers`、文档 §7.1 / §7.2

## 背景

上下文决定上限，但每一层上下文都是真金白银的 token。三层全开等于放弃成本控制。

## 决策

| 层级 | 内容 | 策略 |
| --- | --- | --- |
| L1 | diff 本体 + 邻接上下文行（默认 ±3） | 始终启用 |
| L2 | 变更所在方法完整源码、imports、被引用类型签名 | **默认启用**（性价比最高） |
| L3 | 反向引用、相似实现、历史评论 | 默认关闭，命中条件才升级 |

L2 → L3 的触发条件（`l3_triggers`，命中任一）：

1. 变更了公共方法签名
2. 变更涉及并发原语（锁、原子类、线程池）
3. 变更涉及事务注解或 SQL
4. 变更涉及权限校验逻辑
5. 模型在 Scan 阶段标记 `needs_more_context: true`（阶段二）

## 理由

L2 是"从废话到有判断力"的分界线：没有方法上下文，模型只能给出"建议加空值判断"；
有了完整方法，它才能判断"这个 null 其实上游已经保证了"。

L3 的成本随仓库规模增长，收益却只在特定场景出现（判断影响面、判断是否符合项目既有约定），
因此按条件触发而非默认开启。

## 后果

- 默认成本与"变更行数"线性相关，与仓库总行数无关（§10.1 的增长曲线要求）；
- 达到全局预算 80% 时停止 L3、100% 时终止剩余分块，二者都会写进 summary 的降级说明；
- `ACRA_CONTEXT_LEVEL_MAX` 与 `--level` 可覆盖，用于调试与 A/B。
