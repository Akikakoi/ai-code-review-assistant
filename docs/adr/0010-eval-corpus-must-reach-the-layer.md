# 0010 · 评估语料必须能触达它要测的那一层

- 状态：已采纳
- 日期：2026-09-15
- 相关：`src/acra/eval/defects.py`、`src/acra/eval/static_cases.py`、文档 §4.5 / §11.1

## 背景

"静态分析已接入 Semgrep"这件事，曾经有一整套证据链：工具注册表、参数拼装、
SARIF 解析、路径归一化、diff-aware 过滤、超时处理，全都有单测，
`acra doctor` 也能正确报告工具是否可用。

但装好 Semgrep 之后在 20 类注入语料上真跑一遍，结果是 **0 命中**。

原因不在代码，在**语料**：那 20 类模板是照着"让模型识别"写的，
里面的 `Jdbc`、`Mailer`、`Store` 都是自写的桩类。静态规则匹配的是
**已知的真实库 API 与 sink** —— 桩类不在其中，一条也匹配不上。

于是出现一个很隐蔽的假象：**接口就位、单测全绿，但那一层在真实工具 + 真实代码上
从未被验证过。** 这和之前踩过的两个坑是同一类：

- `static-only` 模式声称"仅展示静态检查结果"，实际什么都不展示；
- `SymbolIndex` 方法齐全，但没人往里塞数据，`referenced_types` 恒为空。

## 决策

**凡是要验证某一层，语料里必须有能触达那一层的样本；不能让"用来测 A 的语料"同时
承担"证明 B 可用"的责任。**

具体做法：

1. 缺陷注入语料（`defects.py`）明确只服务于 LLM 路径，不再声称能验证静态层；
2. 新增 `static_cases.py`：用**真实库 API** 写的用例，专门验证静态层。
   每一条都在入库前用真实工具验证过能触发，并记录触发它的规则名；
3. `full_suite()` 把三类语料（注入 / 诱饵 / 静态探针）合在一起，用 `source` 字段区分，
   指标按来源拆解 —— 这样"静态层有没有真的工作"在报告上直接可见。

## 后果与已知限制

**限制一：污点规则需要污点源。**
实测 `Runtime.exec("ping " + param)`、未关闭的 `FileInputStream`、
`ObjectInputStream.readObject()` 这些片段，用 `p/java` **一条都不会被报出来** ——
它们的规则是污点分析型的，需要一个可识别的源（HTTP 参数、Servlet 输入等）。
一个孤立的方法片段没有源就没有流。

因此静态探针目前只覆盖**语法型**规则（例如 SQL 字符串里做拼接）。
要覆盖污点规则，得写真实框架代码（Spring Controller / Servlet），
成本明显更高 —— 这个取舍写在这里，**避免下次把"静态分析没报"误读成"代码没问题"**。

**限制二：静态探针只有 1 条。**
1 条用例只能证明"这条路径能通"，不能证明"静态层整体可靠"。
补齐这一组是后续事项（成本主要在写真实框架代码）。

### 2026-09-15 补记：那 1 条探针当时其实也没有算数

第一次跑全量纯静态基线时，报告里出现了这样一行：

```
类别不同族  1 条（行号命中但类别跨族，按 §11.2 口径不计命中）
```

它对应的就是这条探针 —— **行号是对的，类别被分类器弄反了**。
`classify_rule` 先按关键词猜，而 `_STYLE_HINTS` 里有 `format`，
于是 `java.lang.security.audit.formatted-sql-string` 被归成了 `style`。

后果比"分类不好看"严重得多：评测按"类别同族"判命中，所以这条结论
**既不算命中（FN）、又被记成一次误报（FP）** —— 而它是本组唯一的样本，
于是"静态层能不能工作"在这个仓库里**从来没有真正被证明过**，
报告上看到的却只是"静态层表现很差"。

修法：`classify_rule` 改为**先读 Semgrep 规则的命名空间段**
（`<lang>.lang.<category>.<...>` 里的 `<category>` 就是权威分类），
关键词只作回退；并把裸 `format` 从风格关键词里去掉。
修完后单跑这条探针：`TP=1 / FP=0`，Precision 与 Recall 均 1.000，类别 security。

**这条补记本身又是一个 0010 的实例**：不是"没有样本"，而是**样本被静默判成了不命中**。
语料能触达那一层还不够，**判命中那条链路也得是对的** ——
否则和没有样本一样，只是更难发现。

## 备选方案

- 继续用桩类语料 + 罐装 SARIF 单测：已验证会漏掉真实工具的匹配行为差异，否决。
- 只依赖 `examples/static-demo`（真实 Ruff 路径）：它只覆盖 Python + Ruff，
  不能代表 Java 侧（Semgrep / Checkstyle），覆盖不足。
