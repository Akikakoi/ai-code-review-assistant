# 0002 · 分析阶段划分：两阶段（Scan + Verify），不合并

- 状态：已采纳
- 日期：2026-09-13
- 相关：`src/acra/engine/scan.py`、`src/acra/engine/verify.py`、文档 §4.6

## 背景

降噪最有效的一招是什么？—— 这个问题决定了整个引擎的形状。

## 决策

拆成两次独立的 LLM 调用：

- **Scan（发散）**：便宜档模型、温度 0.2、不设严格门槛，宁多勿漏；
- **Verify（收敛）**：强档模型、温度 0.0、逐条自证，输出 `confirmed / rejected / uncertain`。

禁止在一个 prompt 里同时"找问题"和"判断问题是否成立"。

## 理由

单 prompt 里模型已经写出来的结论会形成沉没成本 —— 它很难在同一个上下文里否定自己，
倾向于自我一致。拆成第二次独立调用后，验证阶段没有沉没成本，拒绝率显著提升。

## 后果

- 成本上升（Verify 的输入是"每条候选 + 其所在方法源码"）；
- 换来的是 §11.2 里 `Verify rejection rate` 这个可观测指标，范围 0.3~0.6；
  低于 0.15 说明 Scan 太严，高于 0.8 说明提示词可能失效或被注入；
- **阶段一未实现 Verify**（`ACRA_VERIFY_ENABLED=false`），但接口已就位、
  Verify 提示词模板已版本化，且"验证被跳过"会写入 `degraded`，避免把"没验证"
  误读成"验证通过"。
