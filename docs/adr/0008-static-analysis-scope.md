# 0008 · 静态分析只扫变更文件，不扫全仓

- 状态：已采纳
- 日期：2026-09-14
- 相关：`src/acra/analysis/static_runner.py`、文档 §4.5 / §10.1

## 背景

静态分析要跑 Semgrep / ESLint / tsc / Ruff 这类工具，它们通常接受"一个目录"。
最直接的做法是把仓库根目录丢给工具，然后从输出里筛出与本次变更相关的告警
（也就是 diff-aware 过滤）。

## 决策

**只把本次变更的文件物化到一个临时目录，在那里跑工具。**

具体做法：

1. 按仓库相对路径把变更文件的 head 内容写入临时目录（保持目录结构）；
2. 一并物化必要的配置文件（`tsconfig.json`、eslint 配置、`pyproject.toml`、`checkstyle.xml` 等）；
3. 工具在临时目录里执行，超时即放弃该工具；
4. 工具输出的绝对路径按"后缀匹配 + 唯一 basename"映射回仓库相对路径；
5. 再按 `added_line_numbers` 做 diff-aware 过滤。

## 理由

- **成本与仓库体积解耦**（§10.1 的硬要求）：成本只应与变更行数相关。
  全仓扫描会让一次 20 行的 PR 付出整个仓库的扫描代价 —— Semgrep 在中等仓库上就是分钟级。
- **同一执行路径覆盖两种形态**：本地工作区与平台侧的裸克隆缓存都能用，
  不需要为后者额外准备一次完整 checkout。
- **先过滤掉不可能相关的告警，再谈语义**：存量代码的历史告警从来就不该进入上下文
  （否则会出现"这个 PR 一个没改的问题被反复提"）。

## 后果与代价

- 必须物化配置文件，否则语言原生 linter 会因为找不到配置**整体报错**，
  把"配置缺失"误报成"代码有问题"——这是这套方案最容易踩的坑，已用测试固化。
- 依赖跨文件分析的规则（例如"未使用的导出"）在只扫变更文件时会漏报。
  这是可接受的：这类规则的价值远低于成本，且阶段三的 L3 反向引用从另一条路覆盖它。
- 工具报的路径形态不可控（绝对路径 / 相对 cwd / 只有文件名 / Windows 盘符大小写），
  因此路径归一化必须容错且**只接受无歧义匹配**，多义就丢弃（见 `_relativize_path`）。

## 备选方案

- 全仓扫描 + 事后过滤：成本不可控，已否决。
- 为每个仓库维护一份持久化的工作区：状态污染与并发问题多，收益不明确。
