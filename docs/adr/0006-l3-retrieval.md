# 0006 · L3 检索实现：小仓库用向量检索，大仓库用符号匹配

- 状态：已采纳（阶段三实现）
- 日期：2026-09-13
- 相关：`src/acra/context/retriever.py`、文档 §7.6

## 背景

L3 里的"相似实现"需要一个检索能力：找出仓库中同类功能的既有写法，
让模型判断这次改动是否违背了项目既有约定。

## 决策

- **仓库规模 < 5000 文件**：向量检索。索引内容为"每个方法的自然语言摘要 + 方法签名"，
  以变更方法的摘要为 query，取 top-3 且相似度 > 0.75，并过滤掉自己。
- **仓库规模 ≥ 5000 文件**：改用符号名精确匹配 + 路径相似度。

## 理由

检索本身不能成为瓶颈。大仓库上建索引与检索的开销会超过它带来的收益，
而此时"同类功能通常命名相似"这个先验足够强，精确匹配的性价比更高。

## 后果

- 命中后注入格式固定为"仓库中类似的既有实现（供参考项目约定）"，
  并在提示词里明确 **这是约定参照，不是待审代码** —— 否则模型会去评审参照代码；
- 反向引用（`get_callers`）走符号索引，O(1) 命中，不受仓库规模影响；
- 词表/嵌入模型一旦更换，`prompt_template_version` 不需要动，但需要重建索引缓存
  （缓存键含 commit sha，天然按次失效）。
