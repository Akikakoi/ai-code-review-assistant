# 0006 · L3 检索实现：小仓库用向量检索，大仓库用符号匹配

- 状态：**部分实现**（符号匹配已落地；向量路径待办，见文末补记）
- 日期：2026-09-13
- 相关：`src/acra/context/retriever.py`、文档 §7.6

## 背景

L3 里的"相似实现"需要一个检索能力：找出仓库中同类功能的既有写法，
让模型判断这次改动是否违背了项目既有约定。

## 决策

- **仓库规模 < 5000 文件**：向量检索。索引内容为"每个方法的自然语言摘要 + 方法签名"，
  以变更方法的摘要为 query，取 top-3 且相似度 > 0.75，并过滤掉自己。
- **仓库规模 ≥ 5000 文件**：改用符号名精确匹配 + 路径相似度。

## 理由

检索本身不能成为瓶颈。大仓库上建索引与检索的开销会超过它带来的收益，
而此时"同类功能通常命名相似"这个先验足够强，精确匹配的性价比更高。

## 后果

- 命中后注入格式固定为"仓库中类似的既有实现（供参考项目约定）"，
  并在提示词里明确 **这是约定参照，不是待审代码** —— 否则模型会去评审参照代码；
- 反向引用（`get_callers`）走符号索引，O(1) 命中，不受仓库规模影响；
- 词表/嵌入模型一旦更换，`prompt_template_version` 不需要动，但需要重建索引缓存
  （缓存键含 commit sha，天然按次失效）。

## 2026-09-15 补记：先把三层线索接通，向量路径仍待办

补记的原因：这一项此前只做到"接口在、渲染在、提示词留了位置"，**没有任何东西去填**。
`callers` / `similar_impls` 恒为空列表，而空列表是**合法返回值** ——
和"确实没有调用方"长得一模一样。于是"L3 已就位"这个说法一直没被证伪过。

本轮接通了三层线索，并把两条与本 ADR 有关的偏离写在这里：

**一、向量路径未实现，且不静默退化。**
它需要 embedding 提供方，以及一次"为每个方法生成摘要"的预生成 —— 都是独立依赖。
当前**任何规模都走符号匹配**，`L3Clues.notes` 会明说
"向量检索未实现，已退化为符号名匹配（仓库 N 个文件，低于 5000 的阈值本应走向量）"。
理由与整个项目的纪律一致：`L3 跑了但没找到` 与 `L3 根本没按预期跑` 在报告上完全一样，
而处置方式相反 —— 前者可以接受，后者是缺陷。

**二、反向引用不走符号索引，改为有配额的候选扫描。**
本 ADR 原写"走符号索引、O(1) 命中"，但那个索引只对**变更文件及其引用类型**按需建立
（§7.5 的 L2 预算），不是全仓索引 —— 拿它查调用方只会稳定地返回空。
现在按路径邻近度（同目录 → 同顶层目录 → 其余）在**有配额**的文件集合上做符号名精确匹配，
并把"配额是否用尽"如实上报：用尽意味着线索可能不完整（降级），只是没找到则不是。

**三、相似实现的两个实现细节**（都会显著影响线索质量）：

- 匹配到的名字必须**有信息量**：`__init__` / `main` 这类名字对任何文件都是 1.0 匹配，
  实测变更点落在 `__init__` 时，top-3 相似实现全是各文件的 `__init__` —— 纯噪音；
- 注入前保留 0.75 阈值，与向量路径共用"只注入足够像的"语义
  （符号匹配下同名 = 1.0、同族前后缀 = 0.8）。

**四、顺手修掉一个让 L3 永远不生效的缺口。**
`l3_triggers` 算出来的触发条件此前**没有任何效果**：`level` 仍停在配置上限（默认 2），
而 L3 那一段要求 `level >= 3`。现在触发命中会把该文件升到 3，
并按实际用到的最高层级上报 `context_level_max` —— 否则 summary 里会写着"L1 + L2"
而 L3 线索其实已经注进去了。

**仍未验证**：向量路径（需要 embedding 提供方），以及历史评论在真实跨 PR 场景下的效果
（本地验证时结论库为空，走的是"查得到但为空"这条分支）。
