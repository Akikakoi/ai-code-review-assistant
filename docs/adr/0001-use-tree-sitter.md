# 0001 · 代码解析方案：tree-sitter，不用正则

- 状态：已采纳
- 日期：2026-09-13
- 相关：`src/acra/repo/symbol_index.py`、文档 §7.5

## 背景

L2 上下文的核心是"变更行属于哪个方法/类"，分块（§7.4）也依赖语法边界。
需要一套能容错、增量、跨语言的解析能力。

## 决策

采用 tree-sitter（`tree-sitter` + `tree-sitter-java` + `tree-sitter-typescript`）。

## 理由

- **容错**：正在被审查的代码很可能语法就是错的（这正是评审的价值所在），
  tree-sitter 对破损输入仍然给出可用树，regex 方案在这种输入上会直接错位；
- **精确边界**：方法的起止行必须准确，否则 L2 会截错源码、分块会把方法劈成两半（§7.4）；
- **多语言**：新增一门语言的成本是"装一个 grammar + 配一份容器节点表"（§16 阶段四的验收标准是 ≤ 3 人日）。

## 后果与代价

- 引入了一组需要版本对齐的原生依赖，见 ADR 0007；
- 超大文件（> 2MB）不再走 tree-sitter，改为开窗降级（`MAX_PARSE_BYTES`）；
- grammar 缺失时**不静默丢上下文**，而是开窗并写入 `degraded` 说明（文档 P7）。

## 备选方案

- 正则 / 括号计数：对 lambda、内部类、注解嵌套的边界判断不可靠，已否决为主方案，
  但仍作为 `window_span` 的兜底存在。
- javac / tsc 自带 AST：需要能编译（依赖齐全）才能解析，且语言绑定过重。
